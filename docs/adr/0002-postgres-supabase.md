# ADR-0002：PostgreSQL + Supabase 作为 MVP 数据平台

## 状态

建议接受

## 背景

人物、分组、提醒规则和关怀记录存在稳定关系，需要事务、唯一约束、权限隔离和可迁移的数据模型。团队需要尽快获得认证、数据库、存储和定时任务能力。

## 决策

主数据库使用 PostgreSQL，MVP 由 Supabase 提供托管认证、数据库、对象存储、边缘函数和 RLS。

## 影响

优势是开发快、数据模型标准、可使用 SQL 迁移；不足是存在供应商依赖和中国大陆网络可达性风险。因此业务逻辑不绑定私有数据库特性，保留迁移至腾讯云 PostgreSQL 与 Node 服务的路径。

## 备选方案

- Firebase/Firestore：关系查询与事务模型不如 PostgreSQL 贴合。
- 自建 Node + PostgreSQL：控制力更强，但首版运维成本高。
- 纯 SQLite：适合本地原型，不适合服务端提醒与多端同步。
