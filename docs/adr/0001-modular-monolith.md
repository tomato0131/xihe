# ADR-0001：采用模块化单体

## 状态

建议接受

## 背景

羲和处于 MVP 阶段，团队小、需求仍会快速变化。系统需要人物、分组、生日、导入、提醒和关怀记录，但尚无独立扩缩容需求。

## 决策

使用单仓库、单数据库和少量服务端函数，通过代码模块与数据库边界组织领域，不引入微服务。

## 影响

优势是部署简单、调试直接、Vibe Coding 迭代快；不足是模块不能独立扩缩容。若未来企业版通知量显著增长，可先拆出通知任务模块，而不是提前拆分全部服务。

## 备选方案

- 微服务：运维和分布式一致性成本过高，暂不采用。
- 纯前端本地应用：无法可靠实现跨设备同步和服务端提醒，暂不采用。
